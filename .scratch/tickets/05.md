Part of the Retail ERP first-release spec (#1).

## What to build

The append-only stock ledger foundation, inventory search, and the Postgres integration test harness every stock-writing ticket reuses.

- `StockMovement` (append-only): product, store, quantity change, balance before, balance after, movement type (RECEIPT, SALE, ADJUSTMENT), source document reference, actor, timestamp. Confirmed movements are immutable.
- `StockBalance`: current quantity per (product, store), updated inside the same transaction that inserts the movement.
- The single-transaction + conditional-update primitive (reject when the latest balance is insufficient; never trust a browser-sent value) and a unique document-numbering utility.
- INV-01 stock search/low-stock view: search by SKU, product name, store; show current quantity, unit, reorder threshold, and low-stock status (quantity <= threshold).
- Set up the Postgres integration test harness (seam 4) that resets to the TOR Section 8.1 fixture before each scenario.

`Covers:` INV-01, INV-02, INV-03, Section 4.3 (unique document numbers, transaction-time snapshots).
`Demo:` Stock search by SKU/name/store shows quantity, unit, threshold, and low-stock status; a scripted movement updates the balance transactionally and appends an immutable ledger row; the integration harness runs green against real Postgres with the Section 8.1 fixture.
`Seams:` 1 (API controller spec), 2 (Zod schema test), 3 (web component test), 4 (Postgres integration).

## Acceptance criteria

- A stock movement records product, store, quantity change, balance before/after, type, source document, actor, and timestamp, and updates the current balance in the same transaction, observable at seam 4. (Fails today: no ledger or balance models exist.)
- A balance can never go negative and a confirmed movement cannot be edited or deleted, observable at seam 4.
- If the stock update fails, the whole transaction rolls back (no orphan movement or balance drift), observable at seam 4.
- Document numbers are unique, observable at seam 4.
- INV-01 search returns current quantity, unit, threshold, and correct low-stock flag, observable at seams 1 and 3.
- The Postgres integration harness resets to the Section 8.1 fixture before each scenario, demonstrated by a passing fixture-reset test at seam 4.
