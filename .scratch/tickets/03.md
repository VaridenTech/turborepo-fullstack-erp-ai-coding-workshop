Part of the Retail ERP first-release spec (#1).

## What to build

Suppliers master data.

- `Supplier` model (unique code, name, contact details) with a contract, a NestJS module, and an Administrator UI to create, edit, and list suppliers.
- Reuse the pagination, list states, and Thai error envelope established in the stores ticket.

`Covers:` MD-03 (suppliers).
`Demo:` An Administrator creates SUP01 SupplyOne Co Ltd and sees it in a paginated, newest-first supplier list.
`Seams:` 1 (API controller spec), 2 (Zod schema test), 3 (web component test).

## Acceptance criteria

- Creating a supplier with a unique code persists and returns it; the list is newest-first and paginated. (Fails today: no Supplier model or routes exist.)
- A duplicate supplier code is rejected with the Thai error envelope, observable at seam 1.
- Missing required supplier fields are rejected by the Zod schema (seam 2) and the API (seam 1).
- Non-Administrator access is rejected at the API, observable at seam 1.
